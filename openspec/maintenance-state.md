# Maintenance state

## Scheduled dependency review

- Upstream OpenPencil releases are checked daily by `scripts/resolve_release.py`; a build runs only when the version or `latest` is not already published.
- Docker base tags are maintained through Dependabot and resolved to linux/amd64 digests by `scripts/bases.py`.
- GitHub Actions and the deployment and smoke Compose image tags are maintained through Dependabot.
- Cloud runtime dependencies are refreshed with `bun update` inside the image build; the bridge installs its committed lockfile.

Record reviewed base-image or toolchain findings here when a scheduled run cannot update an input automatically.

- The daily `04:17` schedule observed so far actually starts between `11:00` and `13:00` UTC, and a scheduled run skips the build when the newest release is already published. On 2026-11-22 the run started at 12:35:16 UTC, resolved `0.17.0-beta.7` and finished in 11 seconds; stable `v0.17.0` was published at 12:35:42 UTC, 26 seconds after the run resolved. A manual dispatch of the same workflow covered the missed release without changing policy.
- `deploy/` and `cloud/smoke.compose.yml` use `chrislusf/seaweedfs:4.54`, `amazon/aws-cli:2.41.2` and, in `deploy/`, `axllent/mailpit:v1.34.0`. Grouped `docker-compose` Dependabot entries cover both directories. PostgreSQL stays on `17-alpine`; Dependabot proposed `19-alpine`, so both entries now ignore major PostgreSQL updates and a new major remains a reviewed manual change.
- Upstream declares `@hono/node-server` `^1.19.17` and `image-size` `^2.0.4`, so the required `bun update` cannot leave the `1.x` line or reach the advisory-free `image-size` range for every nested copy. `bun audit` after the update reports `@hono/node-server` 1.19.x (moderate, `serveStatic` path decoding, fixed in 2.1.3), nested `image-size` 1.2.1 inside `pptxgenjs` (high, DoS through malformed image headers), `nodemailer` 9.1.1 (ten moderate and two high address/SMTP parser issues fixed only in 10.x) and `glob`/`minimatch` under `@vue-email/render` (moderate). The root `image-size` is 2.1.0, outside the affected range. These need an upstream release or a deliberate override, and a release build must not patch around them.
- Reviewed the upstream advisories published on 2026-11-22. `GHSA-6r2v-cq7x-fvh6` (medium) is patched in `@open-pencil/mcp` 0.17.0-beta.6 and covers the desktop server's `/rpc` and `/files` routes; the bridge exposes neither. `GHSA-x4rx-8c38-9hw8` (high) is patched in `@open-pencil/dom-css` 0.17.0-beta.6 and the 0.17.0 packages carry it. `GHSA-g2vj-wpg5-vqvh` (critical) is patched in 0.15.0 and covered the old public Trystero rooms; Cloud uses authenticated relay tickets.
- A push that touches a Cloud workflow path rebuilds and republishes the same release even when it is already published, and the build is not reproducible because `bun update` resolves newer dependencies. The version tag and `latest` therefore move to a new digest without a new upstream release; the recorded identity below is the current one, not a permanent one.
- Dependabot merged `playwright:v1.65.1-noble` for the Cloud builder on 2026-11-16 after its pull-request build and smoke test passed. The weekly `docker` run also proposed it; keep proposed base tags within the supported majors.

## MCP bridge review

- The original save path rebased an unchanged snapshot onto a newer Cloud revision after a conflict. The local correction uses the bridge's known revision and reports conflicts instead. A disposable Cloud document test confirmed that an external revision makes a stale bridge save fail without changing that revision. Two headless peers exchanged edits in both directions and a saved revision contained both edits.
- A successful image build and startup health check do not establish collaboration or durable-save correctness.
- Reviewed `v0.17.0-beta.5` on 2026-11-16. The bridge moved from `0.17.0-beta.2` to beta.5 packages and vendored collaboration source. Two beta.5 changes break a naive bump: the raster module dropped `initCanvasKit`, and the MCP registry now registers `save_document` and `close_document` where beta.2 had `save_file` and `close_file`. The bridge takes CanvasKit from `@open-pencil/core/canvaskit`, hides the registry's app-only file tools and answers `close_document`.
- Verified against a disposable beta.5 stack: room seeding from a stored revision, concurrent edits in both directions, a save holding both edits, a stale save and a save after an external revision both rejected with 409 without overwriting, recovery after restarting the bridge, and the renamed `close_document` command.
- Verified in Playwright Chromium (the sandbox Obscura engine reports a missing CSS `@property` and cannot run the editor) against the disposable beta.5 stack: the editor loads a Cloud document, a shape created through the bridge appears in the layer panel without a reload, an arrow-key nudge made in the browser changes the node the bridge reads, and the change survives a bridge restart after a saved revision. The OpenChamber desktop panel was not part of this check.
- A server `minimum_editor_version` of `99.0.0` returned `426 editor_outdated` for a request naming `0.17.0-beta.5` and refused the browser editor, while the bridge opened, edited and saved because it names no editor version. This matches the upstream support boundary for MCP clients.
- At the account's storage limit the collaboration ticket reports `permission: view` with `readOnly: storage-limit`; the bridge refuses to open the document with a view-only message and attempts no write.
- The bridge sends only binary relay frames. The beta.5 relay heartbeat is a text `ping` the bridge never sends, and the beta.4 relay accepts the bridge without it.
- The published bridge image also ran against the published beta.4 image: open, create, save, an external revision, a stale-save conflict and restart recovery all behaved as on beta.5.
- `scripts/publish_mcp.py` writes `sha-<commit>` and moves `latest` and `0.1.0` only for an equal or descendant commit. Current published identity: `latest`, `0.1.0` and `sha-cef3ab61847a` are manifest `sha256:c427824f66cc6bf1af4792ae9a389026f125ad31163b1ebf1c9e27a8334f0aef`, revision `cef3ab61847aca81b69a7f21d80d93a138ebf665`, version `0.1.0`.
- Reviewed `v0.17.0` on 2026-11-23. The bridge moved from beta.5 to `0.17.0` packages, added `@open-pencil/std`, and replaced the vendored collaboration source. The vendored change is small: `document/sync.ts` gains an optional `comments` room sync, and two imports move to `@open-pencil/std/random` and `@open-pencil/std/arrays`. The relay frames and `RELAY_SERVER_PEER` are unchanged. The 111-tool registry still uses the same tool names, so the bridge's disabled-tool list needs no change.
- Verified against a disposable 0.17.0 stack: seeding from a stored revision, two peers seeing each other's edits, a save holding both edits, a stale save and an external revision both rejected with 409 without overwriting, and recovery after restarting a bridge. Saved revisions loaded headlessly contained the seeded layers and both peers' edits.
- Observed limit: an external revision written without joining the room is not merged into an existing room. After a restart the bridge downloaded that revision as its base but applied the room state, and its next save produced a new revision from the room content. The save did not overwrite a newer revision with a stale base.
- The bridge base is now resolved to a linux/amd64 digest by `scripts/bases.py` in the MCP workflow, and Dependabot covers `mcp/` Docker tags with a Bun-major ignore.
- Not verified: browser editing through the OpenChamber desktop panel, natural session expiry against 0.17.0, simultaneous room seeding by several peers, and every one of the 111 tools on 0.17.0.
